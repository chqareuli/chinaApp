1. უცვლელი ძირითადი საზღვარი
Parser segmentation ≠ ახალი Editorial data structure.
Legacy token-ები — ZH_RUN, KA_RUN, ZH_SEGMENT, KA_SEGMENT, DBL_ZH_RUN და LINKISH_RUN — შეიძლება საჭირო იყოს ძველ Record-ებში საზღვრების დასადგენად. ისინი Migration/Parser construct-ებია და ახალ Database-ში ავტომატურად არ უნდა გადაიქცეს Table-ებად, Entity-ებად ან Editable level-ებად.

5. Homograph migration
ჩვეულებრივი Entry-ებისთვის ხელოვნური Homograph 1 არ შეიქმნას.
დასაშვები Target cardinality არის 0 ან ≥2 Homograph.
თითოეული Homograph უკავშირდება ერთ Entry Pronunciation-ს; ერთი Pronunciation შეიძლება რამდენიმე Homograph-მა გაიზიაროს.
Homograph-ის Visible label მიიღება Headword-ის, მინიჭებული Pronunciation-ის, Sibling distribution-ისა და order-ის საფუძველზე.
თუ ყველა Homograph ერთსა და იმავე Pronunciation-ს იყენებს, Display უნდა იყოს Headword + number (მაგ., 从 1, 从 2).
თუ Pronunciation-ები განსხვავდება, განმეორებულ Pronunciation-ს ენიჭება Subgroup number (hé 1, hé 2), ხოლო უნიკალური Pronunciation ნაჩვენებია ნომრის გარეშე.
